# Lista delle Attività per il Chiarimento + Brainstorming

## Analisi
1. [ ] Leggere `spec.md` del progetto e ispezionare il codebase per vincoli visibili
2. [ ] Identificare **ambiguità puntuali** (marker `[?]`, TODO, frasi vaghe)
3. [ ] Identificare **punti decisionali** (stack, storage, architettura, modello dati, gestione errori, testing, deploy)

## Brainstorming (obbligatorio)
4. [ ] Per ogni punto decisionale, presentare 2-4 alternative con `pro`/`contro`/`quando conviene`
5. [ ] Dichiarare la raccomandazione (senza imporla)
6. [ ] Aprire domanda focalizzata con `AskUserQuestion`
7. [ ] Discutere eventuali alternative proposte dallo sviluppatore

## Convergenza
8. [ ] Domande chiuse per ambiguità puntuali residue
9. [ ] Verificare/proporre Non-Goals (3-5 candidati se mancano)
10. [ ] Aggiornare `spec.md` con sezione **"Decisioni prese"** (decisione + alternative scartate + motivazione)
11. [ ] Rimuovere marker `[?]` risolti; marcare i residui come `[?risolvere-dopo: <motivo>]`
